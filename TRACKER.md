This is a deliberate exception to "no third-party packages" and "no network calls" — every place those principles were written down (README, AGENTS.md, PROJECT_SPEC.md, `rules/ios-swift.md`, `rules/secrets-and-config.md`) was rewritten in the same change so the docs stop contradicting the code. Squatter is `LSUIElement` with no windows, so a scheduled check that finds an update while the popover is closed shows nothing — Sparkle 2.2+'s gentle reminders hold the found version (`SparkleUpdater.pendingUpdateVersion`) instead of opening an alert behind everything; a dot appears on the footer gear and Settings › About offers Install Update, which is a normal user-initiated check and so Sparkle presents it in focus. - **2026-08-30** — Tuned the two new symbol animations and added a third (owner: "animation speed is too slow", then "make the refresh icon faster, 0.5", then "same for settings icon"). The rotation was the real complaint and the cause was arithmetic I had not checked: SwiftUI's continuous rotate runs about a second per turn, so the 400 ms hold was showing roughly a **third** of a revolution, slowly — the opposite of the "one clean turn" the hold was introduced for. Now `.speed(5)` against a 200 ms hold, which is one turn; the pairing is documented in both files because changing either alone reintroduces the partial-turn bug. "0.5" was read as half the duration, since the two readings that take 0.5 literally (a 0.5 s turn, or `.speed(0.5)`) are both *slower* than what was already there — flagged in the reply rather than silently chosen. The eye's replace also went to `.easeInOut(duration: 0.2)` from `.default`'s ~0.35 s. The gear is **bounce, not rotate**: per the HIG it is acknowledging a click rather than reporting work, and it fires on close as well as open since the popover hangs below the button and leaves the gear visible. Bounce keeps its stock speed on purpose — its elastic timing is the thing that makes it read as a bounce (E2-239).

- **2026-08-29** — The footer's refresh arrow rotates while it scans (owner: "do the same for the refresh icon", with a Rotate / By Layer / Default-direction screenshot). Unlike the eye, this one could not just take an effect modifier: the button **already had** an indicator, swapping the arrow for a `ProgressView` while `isRefreshing`, so an animated arrow and the spinner would have been two indicators competing for one 13 pt slot. Asked rather than guessed, and the owner chose the arrow *as* the indicator — `.symbolEffect(.rotate, options: .repeat(.continuous), isActive: model.isRefreshing)`, `ProgressView` deleted. That is also the HIG's own example for Rotate ("when a task is in progress, rotation confirms that it's working as expected"), and it drops a width change under the button, since the spinner and the glyph did not measure the same. **The interesting half is in the model, not the view**: a local `lsof` scan returns in well under 100 ms, so a rotation bound honestly to the scan's duration would stop a fraction of a turn in and read as a twitch. `minimumRefreshDisplay` (injectable alongside `forceKillGrace`/`badgeInterval`) holds `isRefreshing` open (200 ms, paired with a 5x rotation speed — see the tuning entry above), and the hold is placed **after** every state update in `scan` — the rows, counts and error are on screen immediately and only the arrow is still turning, so this delays feedback, never data. A slow scan overruns the hold and keeps spinning on its own; `lsof`'s ceiling is 10 s (`ProcessRunner.defaultTimeout`), which is exactly the case that made dropping the indicator for a one-shot turn the wrong option. The hold is gated on `showingProgress`, so background polls skip it — otherwise a hold longer than the poll interval would throttle the list to the indicator's pace for an indicator nobody is showing; that is the second of the two new tests, and it is the one that would catch a real regression. Tests inject `.zero` by default so the suite does not pay the hold on every refresh. 128 tests green (E2-238).

- **2026-08-29** — The footer's ignore toggle animates its icon (owner: "let's animate the ignore icon when hiding/showing ignored ports", pointing at the SF Symbols HIG). `eye`/`eye.slash` is Apple's own worked example of a **Magic Replace** pair — related shapes, where the slash draws on and off rather than one glyph cross-fading into another — so this is `.contentTransition(.symbolEffect(.replace.magic(fallback: .upUp)))`.
